# Why You Might Not Need Redux and Modern State Alternatives

> [!abstract] Architectural Thesis
> 
> Stating "Redux has too much boilerplate" or "its creator regretted it" is an interview trap. Dan Abramov never called Redux a mistake—in his seminal essay _You Might Not Need Redux_, he explained that Redux trades local simplicity for indirection to decouple "what happened" from "how state updates." The modern shift away from Redux happened because **80% of what developers put into Redux was actually Server State (now solved by TanStack Query/SWR)**, while modern tools like **Zustand, Jotai, or Redux Toolkit (RTK)** handle the remaining client state with drastically less cognitive overhead.
> 
>   

## Key Concepts

- **Server State vs. Client State Separation**: Historically, Redux was abused as an in-memory client-side cache for REST APIs. Dedicated server-state tools (TanStack Query, RTK Query) handle caching, background deduplication, and revalidation out of the box, eliminating the need for 80% of custom Redux slices.

- **Legacy Redux vs. Modern Redux Toolkit (RTK)**: Legacy Redux required separate action types, action creators, immutable switch-case reducers, and manual middleware. Modern RTK uses `createSlice` with built-in Immer mutation syntax and autogenerated actions, cutting boilerplate significantly.

- **The Indirection Trade-off**: Redux intentionally enforces strict indirection (UI dispatches serializable Action $\rightarrow$ Middleware intercepts $\rightarrow$ Pure Reducer calculates next state $\rightarrow$ Store emits event). This overhead is overkill for standard forms and UI toggles, but beneficial for strict audit logs and event sourcing.

- **Client State Categories**:

    - **Atomic / Primitive State (Jotai, Recoil)**: State split into independent atoms; components re-render only when specific consumed atoms update (ideal for canvas editors, interactive graphs).

    - **Flux / Store-Based State (Zustand)**: Single or multi-store external state with shallow selector subscriptions, zero Context re-render traps, and minimal boilerplate.

    - **Proxy-Based Mutable State (Valtio)**: Wrap objects in ES6 Proxies to read/mutate state directly with automatic subscription tracking.

## Strong Answers / Talking Points

### 1. The Core Misconception: Dan Abramov and "Boilerplate"

- **What Dan Abramov Actually Said**:

    - In _You Might Not Need Redux_, he pointed out that developers often reach for Redux prematurely before feeling the pain it solves.

    - Redux was designed for apps needing reproducible state snapshots, action serialization, undo/redo stacks, and time-travel debugging.

    - If an app does not need to log actions, replay state, or serialize events across network boundaries, paying the price of three-file indirection makes little sense.

- **The Evolution to RTK**:

    - Complaining about action-type strings, manual immutability spreads, and `connect()` HOCs critiques Redux from 2015. Redux Toolkit has streamlined slice generation and mutation logic since 2019.

### 2. Why Teams Still Move Away From Redux Today

1. **The Rise of Specialized Async Tools**:

    - In 2016, apps used `redux-thunk` or `redux-saga` with manual loading/error/data flags to fetch API data.

    - TanStack Query / SWR provide caching, deduplication, retries, window-focus revalidation, and mutation rollbacks natively, leaving only minimal global UI state to manage.

2. **Bundle Footprint**:

    - `redux` + `react-redux` + `redux-thunk` adds ~15kB–30kB gzip.

    - `zustand` is ~1.2kB gzip and requires zero provider nesting.

3. **Ergonomics & Mental Overhead**:

    - Zustand allows accessing and updating state directly without writing actions, reducers, or wrapping root trees in `<Provider>` components.

### 3. When Redux / RTK Is Still Justified

- **Complex Event-Driven Applications**:

    - Trading terminals, collaborative design canvases, audio workstations, or workflow builders where user interactions trigger complex, chained side effects.

- **Action Serialization & Audit Trails**:

    - When every state change must be serialized, logged to a compliance server, or replayed identically for customer support debugging.

- **Strict Architecture Guardrails**:

    - Large enterprise teams where junior developers might introduce anti-patterns; Redux's strict unidirectional pipeline enforces consistent code structure across hundreds of contributors.

## Code Snippets / Examples

### Redux Toolkit (Modern) vs. Zustand (Minimal)

```typescript
// 1. Redux Toolkit (RTK) Approach: Structured, explicit actions and slices
import { createSlice, configureStore, PayloadAction } from '@reduxjs/toolkit';

interface UIState {
  sidebarOpen: boolean;
  theme: 'light' | 'dark';
}

const uiSlice = createSlice({
  name: 'ui',
  initialState: { sidebarOpen: false, theme: 'light' } as UIState,
  reducers: {
    toggleSidebar: (state) => {
      // Immer allows direct mutation syntax under the hood
      state.sidebarOpen = !state.sidebarOpen;
    },
    setTheme: (state, action: PayloadAction<'light' | 'dark'>) => {
      state.theme = action.payload;
    },
  },
});

export const { toggleSidebar, setTheme } = uiSlice.actions;
export const store = configureStore({ reducer: { ui: uiSlice.reducer } });
```

```typescript
// 2. Zustand Approach: Zero boilerplate, hook-first, no provider needed
import { create } from 'zustand';

interface UIStore {
  sidebarOpen: boolean;
  theme: 'light' | 'dark';
  toggleSidebar: () => void;
  setTheme: (theme: 'light' | 'dark') => void;
}

export const useUIStore = create<UIStore>((set) => ({
  sidebarOpen: false,
  theme: 'light',
  toggleSidebar: () => set((state) => ({ sidebarOpen: !state.sidebarOpen })),
  setTheme: (theme) => set({ theme }),
}));

// Consuming in component: Only re-renders if the selected slice changes
export const SidebarToggle = () => {
  const sidebarOpen = useUIStore((state) => state.sidebarOpen);
  const toggleSidebar = useUIStore((state) => state.toggleSidebar);

  return (
    <button onClick={toggleSidebar}>
      {sidebarOpen ? 'Close Sidebar' : 'Open Sidebar'}
    </button>
  );
};
```
